There's a slightly awkward implementation detail in the current inference code.
Although the model conceptually only needs topology + text for free generation, the released sampler currently selects a reference clip belonging to that object type to construct the inference condition. An object with only cond.npy and no loaded motion isn't considered a usable test object. 
So initially I'd put one innocuous motion on Pilgrim before preprocessing:
```
60–90 frames

small torso sway
tiny weight shift
no major choreography
30 fps
```
Not because UniMate needs to imitate it.
It's basically a registration clip that lets the current data loader instantiate the skeleton.
Later we can patch the sampler to create a condition directly from cond.npy and eliminate this requirement.
That's a cleaner v2.

This deserves care because UniML3D canonicalizes each body according to T-pose, facing direction, scale and grounding. A bad facing annotation can make otherwise good generation look nonsensical.
